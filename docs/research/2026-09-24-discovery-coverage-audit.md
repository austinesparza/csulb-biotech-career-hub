# Discovery coverage audit — 24 September 2026

This is a diagnosis and implementation plan for the graduate internship hub. The [73-lead screenshot audit](./2026-09-24-linkedin-screenshot-audit.md) is a regression sample, not 73 confirmed current Summer 2027 MSc internships. Employer and officer verification remains necessary before public publication.

## Confirmed live state

Read-only queries of the connected production Supabase project on September 24 found **25 archived discovery leads**, last seen September 12, **15 pipeline cycles in the last seven days reporting discovery `disabled`**, and **zero reporting discovery `completed`**. Three enabled `job_sources` are Greenhouse feeds for Flagship Pioneering, Ginkgo Bioworks, and Xaira Therapeutics. The latter two had successful fetches September 24; Flagship's last successful fetch was September 16. Those three sources cannot directly cover J&J, Roche, Nanopath, MD Anderson, IBRI, Aldevron, or the other employers in the screenshot sample.

This does **not** establish that all 73 leads are missing from the private review queue, that all are still open, or that the production runtime has a particular secret missing. It establishes a search execution and configured-source coverage gap.

## Code-path findings

| Stage | Actual path | Failure mode / needed change |
| --- | --- | --- |
| Scheduled search | `pipeline-cycle.ts` defaults discovery to `DISCOVERY_SEARCH_ENABLED === 'true'`; `brave-search.ts` also requires the API key and affirmative storage-rights confirmation. | The live cycles show the search path disabled. Confirm licensed provider rights and production configuration; then run a bounded manual cycle before scheduling. Do not print secrets or bypass provider permissions. |
| Employer coverage | `discovery-runner.ts` searches five employers per day by default, from historical watch plus only the first **50** of the 185-company alumni inventory. | The remaining inventory never enters that universe unless independently in the historical watch. Add complete inventory rotation, explicit high-priority watchlist, per-employer `last searched` telemetry, and a coverage target. Five employers/day is roughly a 10-day circuit even for 50 before queries fail or new employers enter. |
| Query recall | `search-plan.ts` combines large quoted OR groups and sometimes science, opportunity, year, and education in one query. Lane rotation is one lane/day and five results per query. | Split compact query families: employer + internship/co-op; method + intern without year; program names; 2027/Summer terms separately; MSc/graduate terms as a separate arm, never mandatory across all arms. Search official ATS domains and public LinkedIn-indexed pages as lead sources. Compare against screenshot gold set and count what each query finds. |
| Source attribution | `discovery-runner.ts` marks any URL on a recognized ATS hostname as `official_source_found` without verifying that the posting belongs to the hinted employer; search result reachability is assumed. | Resolve ATS tenant, requisition and employer identity, fetch actual page, check availability and record verbatim eligibility/date evidence. Until then label `possible employer source`, never verified-open. Maintain redirect lineage and source snapshots. |
| Lead handoff | `lead-store-supabase.ts` archives `discovery_leads` and observations; discovery does not itself create a review-ready draft or public record. | Add a bounded resolver queue: archived lead → employer-source match → fetched posting/version → evidence-backed extraction → officer `review_tasks`/review queue. Keep unresolved LinkedIn leads archived and visible as leads; no automatic approval. |
| Health | `scripts/ops-doctor.ts` checks schema and Sheet, but has no check for discovery enabled, seven-day completed runs, or lead age. | Surface a warning/error on disabled discovery and stale coverage, with a mode-aware exception only if deliberate suspension is recorded. Include provider errors, per-source freshness, and lead-to-review conversion in routine digest. |

The repository already includes Greenhouse, Ashby, Lever, USAJOBS and plain-page connectors, fallback fetch tiers, evidence-bound extraction and officer approval. There is no need to replace that architecture or treat a model as an authority for open status. The bottlenecks are operating coverage and connecting search leads to the established intake path.

## Repair sequence and acceptance

1. **Restore observability now.** Have the operations health check report discovery disabled, no completed searches in seven days, and stale configured feeds, without making ordinary website traffic fail. Add an alert target for an officer. Record why a provider is suspended.
2. **Expand official-first coverage.** Prioritize screenshot employers and active early-career programs. Review each provider's terms/robots, tenant, feed shape and rate limits before enabling a source. For each source store last success, error, posting count, and canonical requisition ID; handle multi-location copies as one posting. Start with publicly exposed employer ATS/API feeds and program pages. An indexed LinkedIn hit is a pointer to investigate, not a bypass around the employer source.
3. **Enable bounded discovery when rights and credentials are confirmed.** Run a manual dry run and inspect result quality, then schedule with budgets. Search full inventory in rotation and high-priority employers more frequently; separate broad and restrictive query arms. Capture every search result and observation privately, including rejected/closed and off-cycle leads.
4. **Complete the resolver and review bridge.** Do not infer employer control solely from a generic Workday/Greenhouse hostname. Fetch/compare requisition and employer, preserve source evidence and explicit unknowns, deduplicate, triage scientific lane and audience, and create a reviewable officer item. A verified current Apply page is required to label a posting open. No AI output can publish directly.
5. **Measure with a dated benchmark.** Seed labeled cases from the screenshot audit and later officer finds: genuinely graduate-accessible, special affiliation, off-cycle, undergraduate-only, expired, and ambiguous. Report discovery recall at 24/48 hours for *accessible employer postings*, verification precision, false-open count, source coverage, and median discovery-to-officer-review latency. Suggested initial gates: ≥90% recall on the benchmark within 48 hours of an accessible official posting, zero false verified-open claims, and every hard gate evidenced or `unknown`. Review and tune after collecting enough cases.

Recurring agentic searches should run as a bounded **investigator of archived leads and coverage gaps**, with access to safe fetch and employer attribution tools and a daily budget. Agents can suggest new sources, alternate search terms and evidence-backed drafts; they cannot conceal provenance, use compression on evidence extraction, evade login/rate limits, or publish without an officer. A weekly officer digest should list new verified drafts, pending unresolved leads, gaps in employer coverage, deadlines backed by employer text, and runs that silently did no search.
