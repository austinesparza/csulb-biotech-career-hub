## Prevent recurrence

The Vertex record came through manual discovery with `deadline = NULL`, even though the full posting carried a date. The public UI interpreted a null as “no fixed deadline.” Merck's posting used a separate “Job Posting End Date” field and a day-before rule. Both fell outside the older visible date path.

The accompanying code changes: (1) distinguish unverified dates from an employer's explicit rolling policy; (2) parse Vertex's date label, Sanofi's “Closing on,” and Merck's day-before rule; (3) require an officer to confirm the full posting's deadline and allow a private draft correction before approval. Follow-up: schedule a recurrent exact-requisition deadline audit using ATS APIs and retain the source quote beside each normalized date. Recheck missing dates after source changes instead of treating null as permanently undated.
